# 수학 에듀테크 사례집 — 배포 안내

중학교 1학년부터 공통수학2까지 대단원 29개 · 소단원 136개의 성취기준을 담고, 소단원마다 에듀테크 사례를 쌓아 나누는 웹앱입니다. 파일 하나로 동작합니다.

---

## 1. 저장 구조

GitHub Pages는 정적 호스팅이라 서버가 없습니다. 사례와 회원 정보는 Firebase에 저장됩니다. 설정은 파일 안에 들어 있으므로 그대로 올리면 바로 연결됩니다.

연결에 실패하면(인터넷이 끊겼거나 프로젝트가 지워졌을 때) 첫 화면에 안내가 뜨고, 그동안 쓴 내용은 그 브라우저에만 임시로 남습니다.

---

## 2. Firebase 준비 (약 10분)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만듭니다. 무료 Spark 요금제로 충분합니다.
2. **빌드 → Firestore Database** 를 만듭니다. 위치는 `asia-northeast3`(서울)를 권합니다.
3. 사진을 올릴 계획이면 **빌드 → Storage** 도 만듭니다. 사진을 늘 URL로만 넣는다면 건너뛰어도 됩니다.
4. **빌드 → Authentication → 로그인 방법**에서 **이메일/비밀번호**를 켭니다. 아이디 로그인은 내부적으로 이 방식을 씁니다.
5. **프로젝트 설정 → 내 앱 → 웹 앱 추가**로 앱을 만들고 `firebaseConfig` 값을 복사합니다.

### 보안 규칙

함께 드린 `firestore.rules` 와 `storage.rules` 파일의 내용을 각각 Firebase 콘솔의 **규칙** 탭에 붙여넣고 **게시**하세요. 규칙을 게시하지 않으면 회원가입 단계에서 막힙니다.

규칙이 지키는 것은 다음과 같습니다.

- 사례 읽기는 누구나. 쓰기는 승인된 회원만.
- 사례 수정·삭제는 본인 것만. 관리자는 전부.
- 회원가입은 본인 문서만 만들 수 있고, **스스로 관리자나 승인 상태를 줄 수 없습니다.**
- 내 정보 수정은 본인이 하되, 역할과 승인 상태는 바꿀 수 없습니다.
- 회원 승인과 권한 변경은 관리자만.

**최초 관리자가 정해지는 방식** — 처음 가입한 사람이 `appConfig/bootstrap` 문서를 만들고, 그 사람만 관리자로 등록될 수 있습니다. 이 문서는 한 번만 만들어지므로 두 번째 사람부터는 규칙이 자동으로 `승인 대기`로 돌립니다. 판정이 화면이 아니라 서버에서 이뤄지는 구조입니다.

---

## 3. 설정 넣기

`FIREBASE_CONFIG` 는 파일 맨 위에 이미 들어 있습니다. 프로젝트를 옮길 때만 이 값을 바꾸면 됩니다.

```js
const FIREBASE_CONFIG = {
  apiKey: "…",
  authDomain: "…",
  projectId: "…",
  storageBucket: "…",
  messagingSenderId: "…",
  appId: "…"
};
```

> Firebase 웹 API 키는 공개되어도 되는 값입니다. 비밀번호가 아니라 프로젝트를 가리키는 주소에 가깝습니다. 실제 보안은 위의 보안 규칙이 담당합니다.

---

## 4. GitHub Pages에 올리기

1. 파일 이름을 `index.html` 로 바꿉니다.
2. 저장소에 올립니다.
3. **Settings → Pages → Source** 를 `main` 브랜치 `/ (root)` 로 지정합니다.
4. 몇 분 뒤 `https://{사용자}.github.io/{저장소}/` 에서 열립니다.

---

## 5. 데이터 구조

| 컬렉션 | 문서 ID | 내용 |
|---|---|---|
| `caseSummaries` | 사례 ID | `subId, tool, title, tags, author, uid, updatedAt` — 목록·검색·개수에 씁니다 |
| `caseBodies` | 사례 ID | `subId, updatedAt, blocksJson` — 본문 블록을 문자열로 담습니다 |
| `users` | 회원 uid | `loginId, name, school, level, grades, subjects, interested, used, role, status` |
| `appConfig` | `bootstrap` | `ownerUid, createdAt` — 최초 관리자를 한 번만 정하는 표식 |

목록과 본문을 나눈 이유는, 첫 화면에서 136개 소단원의 사례 개수를 보여 주면서도 본문은 열어 본 소단원 것만 읽어 오기 위해서입니다. `caseSummaries` 는 실시간으로 감시하므로 다른 선생님이 사례를 올리면 새로고침 없이 목록에 나타납니다.

Firestore 문서 하나는 1MB를 넘을 수 없어, 본문은 900KB에서 저장을 막습니다. Storage를 연결해 두면 사진은 Storage로 올라가고 본문에는 주소만 남으므로 이 한도에 걸릴 일이 거의 없습니다.

---

## 6. 회원과 승인

로그인 없이도 모든 사례를 **읽을 수** 있습니다. 쓰려면 가입과 승인이 필요합니다.

**회원가입 항목** — 아이디, 이름, 비밀번호, 소속 학교, 학교급(중/고), 담당 학년(중학교, 복수 선택) 또는 담당 과목(고등학교, 복수 선택), 관심 있는 에듀테크, 사용해 본 에듀테크.

담당 과목 목록은 2022 개정 고등학교 수학 과목 구성을 따릅니다.

| 구분 | 과목 |
|---|---|
| 공통 과목 | 공통수학1, 공통수학2, 기본수학1, 기본수학2 |
| 일반 선택 | 대수, 미적분Ⅰ, 확률과 통계 |
| 진로 선택 | 미적분Ⅱ, 기하, 경제 수학, 인공지능 수학, 직무 수학 |
| 융합 선택 | 수학과 문화, 실용 통계, 수학과제 탐구 |

**에듀테크 목록** (관심 / 사용 경험 모두 복수 선택)

| 분류 | 도구 |
|---|---|
| 동적 시각화 | 지오지브라, 데스모스, 알지오매스 |
| 게임형 평가 | 카훗, 블루킷, 띵커벨, ZEP Quiz, 퀴즈앤 |
| 문제 진단 | AI 코스웨어, 애스크매스, EBS 단추 |
| 학습 관리 | 구글 클래스룸, 클래스팅, 노션, 패들렛 |
| 맞춤형 도구 제작 | 바이브코딩 |

이 목록은 사례를 쓸 때 도구 이름 칸에서도 자동완성으로 나옵니다.

**내 정보 수정** — 로그인하면 오른쪽 위에 **내 정보 수정** 버튼이 생깁니다. 아이디를 뺀 모든 항목(이름, 소속 학교, 학교급, 담당 학년·과목, 관심·사용 에듀테크)을 바꿀 수 있습니다. 이름을 바꾸면 이미 쓴 사례의 작성자 표기도 함께 바뀝니다. 비밀번호를 바꿀 때는 현재 비밀번호를 한 번 더 확인합니다.

**승인 절차** — 가입하면 `승인 대기` 상태가 됩니다. 관리자가 오른쪽 위 **회원 관리**에서 승인해야 사례를 쓸 수 있습니다. 승인 대기 중에도 다른 선생님의 사례는 읽을 수 있습니다.

**관리자** — **맨 처음 가입한 사람이 자동으로 관리자**가 되니, 배포한 뒤 직접 먼저 가입해 두세요. 관리자에게만 **회원 관리** 버튼이 보이며, 가입 승인·거절, 다른 회원을 관리자로 올리기, 이용 정지, 모든 사례 수정·삭제를 할 수 있습니다. 버튼에는 대기 중인 신청 수가 표시됩니다. 비로그인 상태에서는 회원 관리와 내 정보 수정이 모두 보이지 않습니다.

**권한 정리**

| | 읽기 | 내 사례 쓰기·수정 | 남의 사례 수정 | 회원 승인 |
|---|---|---|---|---|
| 비로그인 | ○ | × | × | × |
| 승인 대기 | ○ | × | × | × |
| 승인된 회원 | ○ | ○ | × | × |
| 관리자 | ○ | ○ | ○ | ○ |

> 아이디 로그인은 Firebase 이메일 인증 위에 얹어 두었습니다. 아이디 `hong`은 내부적으로 `hong@mathcase.local`로 저장되며 메일이 오가지는 않습니다. Firebase가 이 형식을 거부하면 파일 위쪽 `LOGIN_DOMAIN` 값을 바꾸세요.

## 7. 사진 용량

| 저장 방식 | 한 장 한도 | 넘으면 |
|---|---|---|
| Storage 연결됨 | 3MB | 자동으로 더 줄여 보고, 그래도 크면 저장을 막고 알려 줍니다 |
| Storage 없음 (Firestore에 그대로 담음) | 350KB | 위와 동일 |

사진을 고르면 가로 폭과 화질을 단계적으로 낮춰 가며 한도 안에 들어가는지 자동으로 시도합니다. 성공하면 결과 용량을 알려 주고, 실패하면 저장하지 않고 더 작은 사진을 고르라고 안내합니다. 화질을 지키고 싶다면 이미지 주소(URL)를 붙여넣는 편이 낫습니다.

Storage 한도 3MB는 보안 규칙의 `request.resource.size < 3 * 1024 * 1024` 와 같은 값입니다. 바꾸려면 규칙과 파일 위쪽 `IMG_LIMIT_STORAGE` 를 함께 고쳐 주세요.

---

## 8. 소단원별 HTML로 저장

사례가 있는 소단원에는 **HTML로 저장** 버튼이 있습니다. 그 소단원의 사례만 모아 독립된 HTML 파일로 내려받으며, 서식과 임베드가 그대로 들어 있어 따로 공유하거나 인쇄해도 됩니다.

---

## 9. 잘 안 될 때

**회원가입에서 "Firestore 보안 규칙을 확인해 주세요"가 뜬다**
규칙을 아직 게시하지 않았거나, `firestore.rules` 의 내용과 다릅니다. 콘솔의 규칙 탭 내용이 파일과 같은지 확인하고 **게시** 버튼까지 눌렀는지 보세요.

**"Firebase 콘솔에서 이메일·비밀번호 로그인을 켜 주세요"가 뜬다**
Authentication → 로그인 방법 → 이메일/비밀번호가 꺼져 있습니다.

**첫 가입자인데 관리자가 되지 않았다**
`appConfig/bootstrap` 문서가 이미 있으면 그다음 사람은 일반 회원이 됩니다. 시험 삼아 가입해 본 계정이 있다면 콘솔에서 `appConfig`, `users` 컬렉션과 Authentication의 사용자 목록을 모두 지우고 다시 가입하세요. 아니면 콘솔에서 본인 `users` 문서의 `role` 을 `admin`, `status` 를 `approved` 로 직접 고쳐도 됩니다.

**사진이 안 올라간다**
Storage를 만들지 않았거나 `storage.rules` 를 게시하지 않았습니다. Storage 없이도 앱은 돌아가며, 이때 사진은 350KB까지만 사례 안에 담깁니다.
